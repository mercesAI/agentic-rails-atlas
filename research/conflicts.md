# research/conflicts.md

Source conflicts found while building. Both sources are kept on the site; the primary one is named.

- 2026-10-10, x402scan operator: one research note marked the operator unverified; the repository `Merit-Systems/x402scan` (Apache-2.0) names Merit Systems. Kept "Merit Systems" with the repository as the primary source (ATLAS_FOLLOWUP.md 2.1.15).
- 2026-10-10, x402 license: the seed said docs are CC-BY-4.0 with DCO sign-off; the repository has only an Apache-2.0 LICENSE and CONTRIBUTING.md requires GPG-signed commits. The repository is primary; the seed claim is dropped.
- 2026-10-11, x402 V1 legacy packages: ATLAS_FOLLOWUP.md 2.1.13 says only npm `x402` and `x402-express` are V1 legacy; the x402 repository at f8f8330 keeps six V1 packages in `typescript/packages/legacy/` (`x402`, `x402-axios`, `x402-express`, `x402-fetch`, `x402-hono`, `x402-next`) and the migration guide maps `x402-axios` and `x402-fetch` to `@x402/*` too. The repository is primary. Kept the correction's real point (PyPI `x402` 2.x is V2, not legacy) and listed all six npm legacy packages (claim clm-x402-039).
- 2026-10-11, x402 PayAI fee: ATLAS_FOLLOWUP.md Appendix B says PayAI charges $0.001 per settlement "after the first 1,000"; the cited Wavect comparison (2026-07-12) says 1,000 settlements free in total, not per month. Secondary only; verify on PayAI's own page.
- 2026-10-11, ap2 step-up: the v0.2 normative documents (`docs/ap2/*.md` at e1ea56d) define no step-up and route failures through `unresolved_constraint`; the non-normative Executive Summary (`docs/overview.md`, same commit) still says any party may challenge with 3DS2. The normative spec is primary; correction 2.1.10 stands, with the Executive Summary text noted as legacy wording.
- 2026-10-11, ap2 FIDO payments group name: FIDO's 2025-04-29 release launched a "Payments Working Group (PWG)" co-chaired by Visa and Mastercard; the 2026-04-28 release says "Payments Technical Working Group", chaired by Mastercard and Visa. No source says whether this is a rename. Both kept; the group is treated as pre-existing (correction 2.1.11).
- 2026-10-11, ap2 Checkout JWT signature rule: `specification.md` forbids deterministic signatures (for example Ed25519) for the Checkout JWT; `security_and_privacy_considerations.md` allows them with a salt of sufficient entropy. Both are AP2 v0.2 text; issue 268 (open) tracks the fix. Show both.
- 2026-10-11, ap2 receipt field: `agent_authorization.md` defines the Mandate Receipt field `result` with values `success` and `error`; `payment_receipt.json` and `checkout_receipt.json` use `status` with `Success` and `Error` (issue 374). Field tables follow the schemas.
- 2026-10-11, ap2 reference constraint key: `security_and_privacy_considerations.md` writes `mandate.payment.reference`; `open_payment_mandate.json` defines `payment.reference`. The schema is primary.
- 2026-10-11, ap2 amount units: `open_payment_mandate.json` types `payment.amount_range` `max` and `min` as integers in minor units, but the `payment_mandate.md` example uses `100.50` and `10.00`; `payment.budget` `max` is a `number` with no unit and an example of `1000.00`. The schema is primary for amount_range; budget's unit is unresolved.
- 2026-10-11, ap2 launch partner name: the Google Cloud launch post (2025-09-16) names "Ant International"; `docs/partners.md` at the launch commit e66fc0b lists "Ant Group". Keep the launch post wording for the launch list.
- 2026-10-11, ap2 SD-JWT date: AP2's normative reference dates SD-JWT (RFC 9901) "February 2025"; rfc-editor.org gives November 2025. The RFC Editor is primary.
- 2026-10-11, ucp Shopping TC roster: the UCP announcement of 2026-04-24 names "Greg Smith (Amazon)"; `MAINTAINERS.md` at 95b77fd lists Greg Smith (Google) and Jordan Williams (Amazon). MAINTAINERS.md is the current roster; both shown.
- 2026-10-11, ucp AP2 naming: the ucp.dev "UCP and AP2" page describes a `checkoutSignature` and a CheckoutMandate holding a checkout hash; the v2026-08-25 schema uses `ap2.merchant_authorization` and a `checkout_mandate` that contains the full checkout. The schema is primary.
- 2026-10-11, ucp release notes: v2026-08-25 notes say `ap2_mandates`; the schema name is `dev.ucp.common.payment.ap2_mandate`. The schema is primary.
- 2026-10-11, ucp Microsoft tense: Microsoft's agentic commerce page says "MMC will support" UCP; trade press reports UCP feeds generally available in the US from April 2026. Microsoft's page is primary; its tense is used.
- 2026-10-11, ucp Scenario 3: ATLAS_FOLLOWUP suggests "a Google Pay handler that returns a network token"; Google's UCP FAQ says only `PAN_ONLY` is used for `allowed_auth_methods` on Google AI surfaces. The FAQ is primary.
- 2026-10-11, ucp capability versioning: the v2026-08-25 release notes say "independent capability versioning"; the normative overview pins `dev.ucp.*` capability versions to the release date and lets only third-party extensions version independently. The spec is primary.
- 2026-10-11, erc-8004 contracts license: Solidity files in erc-8004-contracts carry `SPDX-License-Identifier: MIT` (SingletonFactory.sol is CC0-1.0); the README "License" section says "CC0 - Public Domain"; GitHub detects no license file. Use "MIT per file headers; README says CC0".
- 2026-10-11, erc-8004 tradingYield example: the spec (ERCS/erc-8004.md) encodes -3.2% as `value` -32, `valueDecimals` 1; the best-practices Reputation.md table "copied from the spec" shows 32. The spec is primary.
- 2026-10-11, erc-8004 Validation Registry deployment: the contracts README lists no Validation Registry address and calls that part of the spec under discussion; eth_call on 2026-10-11 shows a proxy at 0x8004Cc8439f36fd5F9F049D9fF86523Df6dAAB58 (the mainnet address in scripts/addresses.ts) on Ethereum and Base returning getVersion 2.0.0 and the Identity Registry address. Wording: "specified, not officially deployed".
- 2026-10-11, erc-8004 network count: 8004scan.io shows 30 networks; the official README lists 25 mainnets (Ethereum plus 24). 8004scan's count may include testnets or community deployments.
- 2026-10-11, erc-8004 registration cost: QuickNode (2026) "costs dollars" on mainnet and Cobo (2026-04-28) $1 to $5; eth_estimateGas on 2026-10-11 gives about 203,412 gas, which at 0.067 gwei is cents. Not a contradiction once dated; always show the date.
- 2026-10-11, erc-8004 agent id start: contracts commit of 2025-10-11 moved to 1-indexed agent ids; the current IdentityRegistryUpgradeable mints id 0 first and ownerOf(0) resolves on Ethereum. The deployed code is primary.
- 2026-10-11, erc-8004 testnet Validation address removal date: ATLAS_PROMPT says 2026-01-08; README history shows the address list replaced by "TBC" on 2026-01-06 (f111c84) and the 2026-01-08 list without Validation addresses. Use 2026-01-06.
- 2026-10-11, erc-3643 latest tag: the ERC-3643/ERC-3643 repo marks 4.1.3 (2025-06-12) as latest; the archived TokenySolutions/T-REX repo has 4.1.6 (2024-10-18) plus later betas. Cite both with their repositories.
- 2026-10-11, visa-tap license: sample source files carry "(c) 2025 Visa" plus MIT-style permission text, while `LICENSE.md` binds users to the Visa Developer Center Terms and the TAP Product Terms (2025-10-10). Primary: `LICENSE.md` and the Product Terms.
- 2026-10-11, visa-tap "TAP headers optional": ATLAS_FOLLOWUP.md 2.1.12 dates `draft-card-charge-00` to 2026-10-05; the draft has no date field and the GitHub history of `tempoxyz/mpp-specs` shows the sentence in every version since the file's first commit on 2026-01-05. Primary: the GitHub file history; 2026-10-05 is the snapshot date.
- 2026-10-11, visa-tap Cloudflare example: the 2025-10-24 Cloudflare post's checks require `agent-browser-auth` or `agent-payer-auth`, but its example request uses `tag="web-bot-auth"`. Primary: the Visa specification.
- 2026-10-11, visa-tap directory name: Visa's 2026-06-10 release says "Agentic Directory" in the body and "Agentic Registry" in the subheadline; the 2026-07-02 release says "Agent Directory". Primary: the 2026-06-10 body text.
- 2026-10-11, visa-tap key store: the spec's examples use an Ed25519 `keyid` and point to `https://mcp.visa.com/.well-known/jwks`; the live JWKS holds one RSA key (sandbox CA, CN vic-oauth-jwe.visa.com). Both recorded.
- 2026-10-11, visa-tap liability: stellagent.ai (2026-04) says TAP-approved transactions can shift chargeback liability to Visa; Worldpay (2026-07-30) says no liability shift exists. No Visa source states a shift; Worldpay kept.
