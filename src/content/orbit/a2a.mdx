## What it is

A2A gives an agent a published Agent Card, a JSON document that describes its skills, endpoints and security schemes, plus a task model that a client agent drives across a network boundary. Tasks carry messages and artifacts and move through states such as `input-required`. The public Agent Card is served at `/.well-known/agent-card.json`, and the specification separates the application protocol from its JSON-RPC, gRPC and HTTP transport bindings. <Cite ids="src-gloss-a2a-spec" />

A2A is often compared with MCP: MCP connects one application to the tools and data it uses, while A2A connects agents to other agents. <Cite ids="src-arxiv-2505-02279" />

## Status

A2A is live. Google announced it on 2025-04-09, and the Linux Foundation launched it as a project on 2025-06-23. <Cite ids="src-orbit-a2a-google-announce src-orbit-a2a-lf-press" /> On 2025-08-29 the LF AI and Data Foundation announced that IBM's Agent Communication Protocol (not OpenAI's ACP) was joining forces with A2A. <Cite ids="src-ibm-acp-a2a" /> On 2026-08-17 A2A joined the Agentic AI Foundation (AAIF), the Linux Foundation directed fund that also hosts MCP, as a hosted project, and the A2A project's own post calls it a Growth Stage project there. <Cite ids="src-orbit-a2a-aaif-blog src-orbit-a2a-growth-stage-post src-gloss-aaif-lf" /> AAIF listed ten projects on 2026-11-14, none of them one of the eight payment protocols. <Cite ids="src-orbit-aaif-projects" /> On 2026-11-14 A2A's technical steering committee had nine seats; Bloomberg was added to it on 2026-10-20. <Cite ids="src-orbit-a2a-governance" /> Outside AAIF, the Internet Engineering Task Force (IETF) chartered an Agent Communication Protocols (agentproto) working group on 2026-10-08 to define a dialog management protocol whose context A2A and MCP could carry with their own mechanisms; its charter leaves any change to those protocols to their maintainers, and the group posted its first working group draft, on use cases and requirements, on 2026-11-20. <Cite ids="src-orbit-agentproto-charter src-orbit-agentproto-usecases-wg-draft" />

The latest release is still v1.0.1 (2026-05-28), and the published specification page still names 1.0.0 as the latest released version. <Cite ids="src-orbit-a2a-releases src-gloss-a2a-spec" /> A `v1.1.0-rc` tag of 2026-10-29 on the version 1.1 development branch has no GitHub release. Its text adds a live, bidirectional message channel (`SendLiveMessage`) and a task timeline whose generation counter lets a client send a follow-up only if the task has not changed (`ifGenerationMatch`). These are release candidate features, not part of a released version (as of 2026-11-21). <Cite ids="src-orbit-a2a-v1-1-rc src-orbit-a2a-releases" />

## How it relates to the eight

In the payments orbit A2A is a transport and a container for extensions.

- [AP2](/p/ap2/) calls itself an open extension for A2A (and for MCP and UCP), and its Python samples run merchant, credentials provider and payment processor agents that talk over A2A. <Cite ids="src-ap2-site src-ap2-repo" />
- For [x402](/p/x402/), the `a2a-x402` repository defines the x402 Payments Extension v0.1 with the extension URI `https://github.com/google-a2a/a2a-x402/v0.1`. It defines six payment states: `payment-required`, `payment-submitted`, `payment-verified` and `payment-completed` on the happy path, plus `payment-rejected` and `payment-failed`. <Cite ids="src-ap2-a2a-x402-v01 src-x402-a2a-repo" /> x402 v2 carries a matching A2A transport that signals payment with the task state `input-required` and `x402.payment.status` metadata. <Cite ids="src-x402-transport-a2a-v2" />
- [UCP](/p/ucp/) defines an A2A binding for its checkout capability, and businesses that support it publish an agent card endpoint. <Cite ids="src-ucp-a2a" />
- [ERC-8004](/p/erc-8004/) registration files can list an `A2A` service that points to an agent card, and feedback entries can reference A2A skills, `contextId` and `taskId`. <Cite ids="src-erc-8004-spec" />

No direct A2A binding was found in the cloned specs of ACP, Visa TAP or Mastercard Agent Pay. [MPP](/p/stripe-mpp/)'s specifications have none either as of 2026-10-21: its payment discovery draft names A2A agent cards only as prior art and uses an OpenAPI document for discovery instead. <Cite ids="src-stripe-mpp-discovery src-stripe-mpp-specs-repo" />
