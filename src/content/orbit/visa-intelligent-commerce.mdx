## What it is

Visa Intelligent Commerce (VIC) is the commercial layer around Visa's agent protocols. Visa unveiled it on 2025-04-30 under the heading "Find and Buy with AI", pitching AI-ready cards: tokenized Visa credentials that a user can hand to an AI agent without exposing the card number. <Cite ids="src-visa-vic-pr" />

A user enrolls a card, an agent creates a purchase instruction that the user confirms (Visa Payment Passkeys are the confirmation method Visa names in Europe), and the agent then requests credentials for that instruction. <Cite ids="src-visa-vic-dev src-visa-ar-eu" /> Visa's open-source `visa/ai` toolkit shows the shape of the API: enrollment through `POST /vacp/v1/cards`, then create, update, cancel, credential and confirmation calls under `/vacp/v1/instructions`. The confirmation call reports the outcome back to Visa as a "signal" that Visa says helps resolve disputes. <Cite ids="src-visa-ai-vic-client src-visa-vic-dev" />

## TAP inside VIC

[Visa TAP](/p/visa-tap/) sits inside VIC. TAP is the signature scheme an agent uses to identify itself to a merchant website; VIC supplies the onboarding of agents, the tokens and the payment instructions that the TAP payment container refers to. The TAP specification says a public key associated with Visa implies that the agent takes part in, and complies with, the VIC program requirements. A merchant that verifies TAP is therefore relying on Visa's agent onboarding, which is not public. <Cite ids="src-visa-tap-spec src-visa-tap-pr" />

## Programs around the API

- **Agentic Ready** prepares issuers and merchants to accept agent transactions. It launched in Europe on 2026-03-17 with 21 named early issuers, and Visa announced a global expansion on 2026-04-29. <Cite ids="src-visa-ar-eu src-visa-ar-global" /> On 2026-07-02 Visa said 31 European issuers had completed live agent purchases with merchants such as lastminute.com, and that every Agentic Ready transaction in Europe used Visa Payment Passkeys, supporting Strong Customer Authentication. <Cite ids="src-visa-eu-live" />
- **Intelligent Commerce Connect** (pilot, announced 2026-04-08) is an on-ramp for businesses that accepts agent payments arriving through TAP, MPP, ACP or UCP, and can handle orchestration and PCI compliance for enablers. <Cite ids="src-visa-icc" />
- **Agentic Directory and Agent Score** (announced 2026-06-10): the directory is described as a list of Visa-verified agents and merchants, and Agent Score rates how ready a merchant site is for agents (it scores sites, not agents). The same release calls the directory an "Agentic Registry" in its subheadline. No public list or endpoint was found. <Cite ids="src-visa-jun10" />

## Status

Separate what is live from what is announced. Live: the sandbox API (free in sandbox, production fees by contact), the `visa/ai` toolkit (MIT, last commit 2026-09-30), Agentic Ready transactions in Europe, and partner products such as Crossmint's Agentic Cards API (2026-06-02). <Cite ids="src-visa-vic-dev src-visa-ai-repo src-visa-eu-live src-orbit-crossmint-launch" /> Visa reported "hundreds" of agent-initiated transactions with partners by 2025-12-18. <Cite ids="src-visa-dec18" /> Pilot or announced: Intelligent Commerce Connect, the Agentic Directory and Agent Score. <Cite ids="src-visa-icc src-visa-jun10" />

Since 2025-10-18 Visa's public rulebook, the Visa Core Rules and Visa Product and Service Rules, has carried the program's requirements, most of them in the Product and Service Rules (section 4.1.24). The rules govern Visa and its member institutions and yield to applicable law. In the current edition (2026-04-18), an Agentic Payment Provider must enroll in Visa Intelligent Commerce and register with Visa, directly or via an Agentic Payment Enabler. It must not combine several agent purchases into one transaction, and must get its tokens from Visa or an Agentic Payment Enabler when it uses stored credentials. Within Visa's system, the cardholder is responsible for its actions in an Agentic Transaction as if the cardholder had initiated it. <Cite ids="src-visa-rules-public" /> Visa calls no rule a liability shift and adds no agent-specific dispute condition, fee, interchange rate or 3-D Secure rule. It does require issuers to pay for Agentic Transactions made under a cardholder's payment instructions and not to block them wholesale. From 2026-10-24 it also accepts an Agentic Payment Provider's login ID among the evidence that can defeat a card-absent fraud dispute. <Cite ids="src-visa-rules-public" /> Worldpay (2026-07-30) says no liability shift exists yet. <Cite ids="src-worldpay-liability" /> Visa's reference agent (`visa/vic-reference-agent`) carries an evaluation-only license despite being described as open source. <Cite ids="src-visa-vic-ref-agent" />

## How it relates to the eight

Visa extends VIC beyond its own protocol. It authored the card payment method for [MPP](/p/stripe-mpp/) (`draft-card-charge-00`, where TAP headers are optional) and published a card spec and `mpp-card` SDK built on VIC and TAP on 2026-03-18. <Cite ids="src-stripe-mpp-card-charge src-visa-mpp-card" /> It is a Premier member of the x402 Foundation, and the TAP release says Visa is collaborating with Coinbase on [x402](/p/x402/) interoperability. <Cite ids="src-x402-lf-july src-visa-tap-pr" /> Visa is listed as a [UCP](/p/ucp/) endorser and is a founding validator of Circle's Arc chain. <Cite ids="src-ucp-site src-orbit-circle-arc-mainnet" /> Mastercard's counterpart program is [Agent Pay](/p/mastercard-agent-pay/); both networks use the phrase "agentic token" for different constructs.
