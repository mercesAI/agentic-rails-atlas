## What it is

Visa Intelligent Commerce (VIC) is the commercial layer around Visa's agent protocols. Visa unveiled it on 2025-04-30 under the heading "Find and Buy with AI", pitching AI-ready cards: tokenized Visa credentials that a user can hand to an AI agent without exposing the card number. <Cite ids="src-visa-vic-pr" />

A user enrolls a card, an agent creates a purchase instruction that the user confirms (Visa Payment Passkeys are the confirmation method Visa names in Europe), and the agent then requests credentials for that instruction. <Cite ids="src-visa-vic-dev src-visa-ar-eu src-visa-eu-live" /> Visa's open-source `visa/ai` toolkit shows the shape of the API: enrollment through `POST /vacp/v1/cards`, then create, update, cancel, credential and confirmation calls under `/vacp/v1/instructions`. The confirmation call reports the outcome back to Visa as a "signal" that Visa says helps resolve disputes. <Cite ids="src-visa-ai-vic-client src-visa-vic-dev" /> Visa's public API reference, as seen on 2026-11-14, also has a V2 bundle: `POST /vacp/v2/credentials-for-instruction` enrolls the card inline, records the consumer's approval and returns a credential, and it requires a `purchaseType` of `PURCHASE_HITL`, `PURCHASE_AUTONOMOUS` or `PURCHASE_RECURRING`. <Cite ids="src-visa-vic-v2-apiref" />

## TAP inside VIC

[Visa TAP](/p/visa-tap/) sits inside VIC. TAP is the signature scheme an agent uses to identify itself to a merchant website; VIC supplies the onboarding of agents, the tokens and the payment instructions that the TAP payment container refers to. The TAP specification says a public key associated with Visa implies that the agent takes part in, and complies with, the VIC program requirements. A merchant that verifies TAP is therefore relying on Visa's agent onboarding. <Cite ids="src-visa-tap-spec src-visa-tap-pr" /> Visa's VIC docs, public again on 2026-11-14, outline it: production agents onboard to VIC, TAP, Visa Token Service and Visa Payment Passkeys, and register in the Visa Agent Registry Service (VARS) so that Visa can validate their signatures and merchant encryption keys. The docs also cite a VIC and TAP Client Implementation Guide that they do not link. <Cite ids="src-visa-vic-docs" />

## Programs around the API

- **Agentic Ready** prepares issuers and merchants to accept agent transactions. It launched in Europe on 2026-03-17 with 21 named early issuers, and Visa announced a global expansion on 2026-04-29. <Cite ids="src-visa-ar-eu src-visa-ar-global" /> On 2026-07-02 Visa said 31 European issuers had completed live agent purchases with merchants such as lastminute.com, and that every Agentic Ready transaction in Europe used Visa Payment Passkeys, supporting Strong Customer Authentication. <Cite ids="src-visa-eu-live" />
- **Intelligent Commerce Connect** (pilot, announced 2026-04-08) is an on-ramp for businesses that accepts agent payments arriving through TAP, MPP, ACP or UCP, and can handle orchestration and PCI compliance for enablers. <Cite ids="src-visa-icc" />
- **Agentic Directory and Agent Score** (announced 2026-06-10): the directory is described as a list of Visa-verified agents and merchants, and Agent Score rates how ready a merchant site is for agents (it scores sites, not agents). The same release calls the directory an "Agentic Registry" in its subheadline. No public list or endpoint was found. <Cite ids="src-visa-jun10" />
- **BILL and Billtrust business-to-business pilot** (live, announced 2026-10-20): BILL's Payment Agent, registered using TAP and the Agentic Directory, pays buyer-approved supplier invoices with tokenized credentials, and Billtrust's supplier portals use TAP to recognize, authenticate and admit it, which Visa says can stand in for CAPTCHA and other bot blocking. Visa calls it the first live pilot in which trusted AI agents complete approved invoice payments end to end through supplier portals; it does not call it the directory's first use, and it publishes no transaction counts. <Cite ids="src-visa-bill-billtrust src-visa-commercial-2026-10-21" />

## Status

Separate what is live from what is announced. Live: the sandbox API (free in sandbox, production fees by contact), the `visa/ai` toolkit (MIT, last commit 2026-09-30), Agentic Ready transactions in Europe, the BILL and Billtrust pilot (live, announced 2026-10-20), and partner products such as Crossmint's Agentic Cards API (2026-06-02). <Cite ids="src-visa-vic-dev src-visa-ai-repo src-visa-eu-live src-visa-bill-billtrust src-orbit-crossmint-launch" /> The fee terms come only from Visa's developer page as archived on 2026-10-03. Visa's VIC docs, which asked for sign-in on 2026-10-19, were public again on 2026-11-14, state no fees, and say production access requires TAP, Visa Token Service and Visa Payment Passkeys onboarding plus VARS registration. <Cite ids="src-visa-vic-dev src-visa-vic-docs" /> After relaunching its developer portal in October 2026, Visa said product-specific Agent MCP servers are rolling out, starting with Visa Intelligent Commerce, for anyone with a Visa Developer account. <Cite ids="src-visa-dev-news-2026" /> Visa reported "hundreds" of agent-initiated transactions with partners by 2025-12-18. <Cite ids="src-visa-dec18" /> On its 2026-10-27 earnings call, according to a third-party transcript (reported), Visa's CEO said nearly 50 AI partners were live and in production, that Ramp's agentic bill pay use case on VIC was generally available and that Airwallex was testing VIC-enabled credentials. <Cite ids="src-visa-q4-fy2026-call" /> OpenAI announced [ChatGPT Wallet](/orbit/chatgpt-wallet/) on 2026-11-13 as built in partnership with American Express, Mastercard and Visa, rolling out first in dots for US ChatGPT Pro subscribers; the announcement names no Visa program. <Cite ids="src-openai-chatgpt-wallet" /> Pilot or announced: Intelligent Commerce Connect, the Agentic Directory and Agent Score. <Cite ids="src-visa-icc src-visa-jun10" />

Since 2025-10-18 Visa's public rulebook, the Visa Core Rules and Visa Product and Service Rules, has carried the program's requirements, most of them in the Product and Service Rules. The current edition (2026-10-24) puts them in section 4.1.23, renumbered from 4.1.24 in the April 2026 edition with the same rule IDs, and its summary of changes lists no agentic change. The rules govern Visa and its member institutions and yield to applicable law. An Agentic Payment Provider must enroll in Visa Intelligent Commerce and register with Visa, directly or via an Agentic Payment Enabler. It must not combine several agent purchases into one transaction, and must get its tokens from Visa or an Agentic Payment Enabler when it uses stored credentials. Within Visa's system, the cardholder is responsible for its actions in an Agentic Transaction as if the cardholder had initiated it. <Cite ids="src-visa-rules-public" /> The rules call none of the agent rules a liability shift and add no agent-specific dispute condition, fee or 3-D Secure rule, and Visa's US interchange schedule (2026-10-24 edition, like the April 2026 one) has no agentic category. <Cite ids="src-visa-rules-public src-visa-us-irf-2026-04" /> The VIC product docs (2026-11-14) add a 3-D Secure behavior: US merchants that support it get a "Program Not Supported" response for agentic transactions, while other regions keep 3-D Secure with region-specific treatment. <Cite ids="src-visa-vic-docs" /> The rules do require issuers to pay for Agentic Transactions made under a cardholder's payment instructions and not to block them wholesale. Since 2026-10-24 they also accept an Agentic Payment Provider's login ID among the evidence that can defeat a card-absent fraud dispute. <Cite ids="src-visa-rules-public" /> Worldpay (2026-07-30) says no liability shift exists yet: fraud on properly tokenized agent payments follows existing rules, while disputes short of fraud are unsettled. <Cite ids="src-worldpay-liability" /> Visa's reference agent (`visa/vic-reference-agent`) carries an evaluation-only license despite being described as open source. <Cite ids="src-visa-vic-ref-agent" />

## How it relates to the eight

Visa extends VIC beyond its own protocol. It authored the card payment method for [MPP](/p/stripe-mpp/) (`draft-card-charge-00`, where TAP headers are optional) and published a card spec and `mpp-card` SDK built on VIC and TAP on 2026-03-18. <Cite ids="src-stripe-mpp-card-charge src-visa-mpp-card" /> It is a Premier member of the x402 Foundation, and the TAP release says Visa is collaborating with Coinbase on [x402](/p/x402/) interoperability. <Cite ids="src-x402-lf-july src-visa-tap-pr" /> Visa is listed as a [UCP](/p/ucp/) endorser and is a founding validator of Circle's Arc chain. <Cite ids="src-ucp-site src-orbit-circle-arc-mainnet" /> Mastercard's counterpart program is [Agent Pay](/p/mastercard-agent-pay/); both networks use the phrase "agentic token" for different constructs. <Cite ids="src-stripe-spt src-mc-agentic-tokens" />
