Cloudflare introduced signed agents on 2025-08-28 as an extension of its Verified bots program, for agents that sign their HTTP requests with Web Bot Auth and follow a signed agent policy. <Cite ids="src-orbit-cf-blog-signed-agents" /> Its Verified bots documentation (last updated 2026-11-12) says signed agents are now Verified: as of 2026-07-01 a bot record carries a "Direct versus Intermediary access" field, where Direct means one narrow operator and Intermediary means an agentic service that many end users can operate. Since 2026-11-02 the same page says Cloudflare may revoke Verified status for every bot and agent of an organization that repeatedly breaks the policy. The `cf.bot_management.signed_agent` rules field matches a Verified bot labeled Intermediary and needs an Enterprise plan with Bot Management. <Cite ids="src-cf-verified-bots src-cf-signed-agent-field" /> The 2026-07-01 changelog entry launched BotBase but does not mention the merge, so the docs page is the only source for it. <Cite ids="src-orbit-cf-botbase-changelog" /> On 2026-11-09 the Bots Directory on Cloudflare Radar moved onto BotBase, and its API now gives each bot an access level (`DIRECT` or `INTERMEDIARY`), a content use and one or more categories, which follow BotBase's groups and add a commerce group. <Cite ids="src-orbit-cf-radar-botbase-changelog" /> Cloudflare's verifier accepts only the older string form of the `Signature-Agent` header, not the dictionary form of the current working group draft. <Cite ids="src-orbit-cf-wba-reference" /> Cloudflare checks [Visa TAP](/p/visa-tap/) and [Mastercard Agent Pay](/p/mastercard-agent-pay/) signatures at its edge. <Cite ids="src-visa-tap-cf-blog src-mcap-cloudflare-blog" />

On 2026-11-04 Cloudflare added controls for personal agents, the agents that browse or act for one person. Its AI bot policy setting is now called AI Crawler and Agent access policies: a site sets an overall Agents policy, then Allow (do not block), Block on pages with ads, or Block for each supported personal agent, and Security Analytics shows personal assistants as their own traffic category. <Cite ids="src-orbit-cf-personal-agents-changelog src-orbit-cf-blog-personal-agents" /> Personal agents inherit the Agents policy, Cloudflare recommends allowing them, and new domains allow Search, Agents and Training traffic by default (docs last updated 2026-11-02). <Cite ids="src-orbit-cf-ai-access-policies" /> OpenAI's cloud browser appears in that list as `dots, OpenAI`. <Cite ids="src-openai-commerce-agent-access" /> On 2026-11-05 Cloudflare announced a Trusted Agent Delegation (TAD) coalition, which is meant to examine existing protocols and bring well-defined problems to the IETF, and named MOLE (Moderation Of unLinkable Endorsements) as the intended successor to Private Access Tokens. World's post of 2026-11-12 describes TAD as a coalition that Cloudflare and World introduced together. <Cite ids="src-orbit-cf-blog-tad src-orbit-world-blog-tad" /> As of 2026-11-14 TAD had a whitepaper but no published specification or member list, and MOLE was an IETF 127 BoF, not a chartered working group. <Cite ids="src-orbit-tad-site src-orbit-mole-bof" />
