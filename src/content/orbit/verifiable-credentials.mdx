## What it is

These standards let an issuer sign claims about a subject, let the holder keep them in a wallet, and let a verifier check them later, ideally with only the needed claims shown. Two encodings matter here. The W3C Verifiable Credentials Data Model 2.0 became a Recommendation on 2025-05-15, as part of a family of VC 2.0 specifications W3C announced that day. <Cite ids="src-gloss-vc-2 src-orbit-kya-w3c-vc2-press" /> Decentralized identifiers (DIDs) give issuers and holders resolvable identifiers. DID Core 1.0 has been a Recommendation since 2022-07-19, and DID 1.1 is a Candidate Recommendation Snapshot of 2026-03-05. <Cite ids="src-gloss-did-1 src-orbit-kya-did-1-1" />

The other encoding comes from the IETF. SD-JWT, published as RFC 9901 in November 2025, makes individual JWT claims selectively disclosable and can bind the token to a holder key. <Cite ids="src-mcap-rfc9901" /> SD-JWT VC defines a credential format on top of it. Its revision `draft-ietf-oauth-sd-jwt-vc-19` was posted on 2026-08-31 and sits with the IESG awaiting the area director, so it is not yet an RFC. <Cite ids="src-orbit-kya-sd-jwt-vc-draft" />

Presentation is the last step. OpenID for Verifiable Presentations (OpenID4VP) 1.0 became a final OpenID Foundation specification on 2025-07-09. <Cite ids="src-gloss-openid4vp" /> The W3C Digital Credentials API, which lets a website ask the browser to request a credential from a wallet, was a Working Draft dated 2026-09-04 on 2026-10-11. <Cite ids="src-gloss-dc-api" />

## How it relates to the eight

[AP2](/p/ap2/) v0.2 specifies OpenID4VP with SD-JWT VCs. Delegation travels in OpenID4VP `transaction_data` of type `delegate`, the Digital Credentials API is recommended, and mandates carry `vct` values `mandate.checkout.1` and `mandate.payment.1`, chained with a delegate SD-JWT. AP2 does not reference the VC Data Model or DIDs, so those are the wider family rather than AP2 dependencies. <Cite ids="src-ap2-agent-authorization src-ap2-delegate-sd-jwt" />

Verifiable Intent, the intent layer of [Mastercard Agent Pay](/p/mastercard-agent-pay/), uses SD-JWT per RFC 9901 with key-binding chains (`typ` values `sd+jwt`, `kb-sd-jwt` and `kb-sd-jwt+kb`). Its design notes call it a credential format and say a future guide may define presentation over OpenID4VP. <Cite ids="src-mcap-vi-format src-mcap-vi-rationale" /> Outside the eight, Catena's Agent Commerce Kit v1 uses DIDs and VCs, and its open v2 proposal moves away from VCs toward plain JOSE grants. <Cite ids="src-orbit-kya-ack-repo src-orbit-kya-ack-v2-rfc" />
