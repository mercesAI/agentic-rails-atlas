# Architecture contract

This file is the binding contract between the parts of the Agentic Rails Atlas. Agents that build components, scripts or content must follow it. When a rule here conflicts with a convenience, the rule wins; if the rule is wrong, change it here first and log the change in `private/DECISIONS.md`.

Spec: `private/ATLAS_PROMPT.md`. Schemas: `src/lib/schemas.ts` (Zod 4, shared with Astro content collections in `src/content.config.ts`). Tokens: `src/styles/tokens.css`.

## 1. Stack facts that matter

- Astro 7.3.8, static output, `trailingSlash: 'always'`, directory URLs (`/p/x402/`).
- React 19 islands (`client:visible` by default, `client:load` only for the theme and reading-mode controls, `client:only="react"` only when SSR is impossible).
- Tailwind CSS 4 through `@tailwindcss/vite`; `src/styles/global.css` imports Tailwind and `tokens.css`. Prefer CSS custom properties from `tokens.css` for color; use Tailwind for spacing and layout. Never hard-code hex colors in components.
- Fonts are self-hosted through fontsource packages: `@fontsource-variable/bricolage-grotesque` (headings), `@fontsource-variable/ibm-plex-sans` (body), `@fontsource-variable/jetbrains-mono` (code). Import their CSS once in `src/layouts/Base.astro`.
- MDX through `@astrojs/mdx`; Markdown plugins run on `@astrojs/markdown-remark` (installed explicitly). Code highlighting through Astro's built-in Shiki with dual themes (`defaultColor: false`); the CSS switches `--shiki-light` and `--shiki-dark` by theme.
- Search through `astro-pagefind` (index built at `astro build`). The command palette queries Pagefind on the client and also searches a small build-time JSON index of pages, sections, glossary terms, resources and publications (`src/generated/search-index.json`).
- Path alias `@/*` to `src/*`.
- Scripts run with `tsx`. They import from `src/lib/schemas.ts` and never from `astro:*` virtual modules.

## 3. Data access

`src/lib/content.ts` exposes typed helpers over `astro:content`:
- `getProtocols()` sorted by `order`; `getProtocol(slug)` returns `{ meta, Content, sidecars }` where sidecars are the parsed JSON files or `null` when absent.
- `getSourcesMap()` id to Source; `getClaimsMap(slug)` id to Claim.
- `getFlow(id)`, `getStateMachine(id)`, `getDiagramMeta(id)`.
- `getPageSources(slug)`: the ordered, de-duplicated list of Source ids referenced by the protocol (frontmatter keyFacts claims, every sidecar's `sources`, `claimIds` and the `<Cite>` markers found in the MDX body by a build-time scan). This list drives the footer numbering.

Missing sidecar files must not crash a page: components render an "in progress" placeholder with the section still present (so the coverage checker, not the build, reports the gap).

## 5. Protocol page template

Section order and ids are fixed in `SECTION_IDS` and `SECTION_TITLES` (`src/lib/schemas.ts`). Each section is `<section id="<section-id>" data-section aria-labelledby="<section-id>-h">` with an `<h2 id="<section-id>-h">` whose text is `SECTION_TITLES[id]` prefixed by the letter (for example "B. Detailed explanation"). Headings get a copy-link button.

Header (`components/protocol/ProtocolHeader.astro`): monogram badge (`Monogram.astro`, rounded square in the family hue, no logos), name, tagline, stewards, `StatusDot` + status label, latest version and date, "State as of {lastVerified}" with `FreshnessBadge`, rails chips (ring-style glyph plus label), layer chips, `ReadingModeSwitch` island, jump chips for every section. The header root carries `transition:name={`bubble-${slug}`}` so the home bubble morphs into it with the View Transitions `<ClientRouter />`.

Left rail: sticky `Toc.astro` (section list with read-progress fill, updated by an IntersectionObserver script that also stores read sections in storage key `atlas:read:<slug>` as an array of section ids). Right rail: `KeyFactsCard` and `SectionSources` (sources cited in the section currently in view, driven by the same observer).

Section content sources:
- A: `facts.json` + `meta.keyFacts` + `meta.disambiguation` (Disambiguation callout from Appendix D) + `facts.changedRecently` (ChangedRecently callout).
- B: MDX body of `index.mdx`. Reading modes: text outside `<Mode>` is practitioner text and is also shown in spec mode. `<Mode eli5>...</Mode>` shows only in ELI5. `<Mode spec>...</Mode>` shows only in Spec-deep (field tables, headers, enums, wire examples). In STE mode, section B is hidden and section D is moved up visually (CSS order) and expanded. The `Mode` component renders `<div class="mode-block" data-modes="eli5">` and the CSS in tokens.css does the switching; no JavaScript re-render.
- C: `meta.mainFlow` as `FlowPlayer` island plus the generated Mermaid; `meta.stateMachine` as `StateMachineExplorer` island plus Mermaid; `meta.diagrams[]` as `MermaidDiagram` (hand-written .mmd rendered to SVG). Each diagram shows caption, a "text alternative" disclosure, and a "source of truth" link.
- D: `ste.mdx` rendered inside `SteView` with a side-by-side toggle (`SteCompare`, left: the first paragraphs of section B practitioner text, right: STE description) and `SteReport` (reads `src/generated/ste-report/<slug>.json`).
- E: `personas.json` as `PersonaGrid` (cards) + `ResponsibilityTable`.
- F: `resources.json` as `ResourceList` with GitHub metadata from `src/generated/github/*.json` when present.
- G: publications where `protocols` includes the slug, grouped by `relation` and themes, through `PublicationList`; grey literature separate; BibTeX copy button; a plain sentence when no paper names the protocol.
- H: `security.json` as `ThreatTable` (STRIDE), scenario cards, research findings list, CVE list, and the trust-boundary diagram.
- I: `controls.json` as `ControlsTable` (native support per control), gaps, control points, checklist.
- J: `compliance.json` as `ComplianceTable` (jurisdiction rows by topic) with the "not legal advice" note once.
- K: `observability.json` as `ObservabilityPanel` with the 0 to 5 score.
- L: `ecosystem.json` with `MetricChart` when `chart` exists.
- M: `timeline.json` as `Timeline` (single lane, vertical).
- N: `code.json` as code blocks with SDK and version labels.
- O: `playgrounds/<slug>/Playground.tsx` inside `PlaygroundFrame` (the frame prints "Simulation, no real funds" and the spec version). `meta.playground.status === 'coming-next'` renders the ComingNext card instead.
- P: MDX body region after a `## Compare and compose` marker, or a `<CompareCompose />` component fed by relations.json and compare.json.
- Q: `faq.json` as `Faq` (details elements). R: `open-questions.json`. S: `Quiz` and `Flashcards` islands. T: `NotesPanel` island (per-section notes).

Footer: numbered `SourceList` (from `getPageSources`), last verified, content path, "flag an issue" button (adds a prefilled note).

## 6. Component contracts

All components take typed props from `src/lib/schemas.ts`. Astro components for static rendering, React for interactive islands. Islands are small and self-contained; they receive data as props (serialized JSON), never fetch content at runtime.

- `Cite` (Astro): `ids: string` (space-separated claim ids or source ids). Renders `<sup class="cite"><a href="#src-N" data-cite="...">[N]</a></sup>` where N is the index in `getPageSources`. Resolution: `citations.ts` maps claim ids to their sources. The page sets the current source index in `citations.ts` (`setPageSources(list)`) before rendering `<Content />`; `Cite` reads it. For claim ids, the marker's `title` is the claim text and `data-confidence` is the confidence (a small badge for `unverified`).
- `CitationDrawer` (React, `client:idle`): listens for clicks on `[data-cite]`, shows source title, publisher, type, primary flag, published and accessed dates, confidence of the claim, notes, archive link.
- `FreshnessBadge` (Astro): `date: string`, `buildDate: string` → green under 30 days, amber 30 to 90, red over 90, with text "Verified {date}".
- `StatusDot` (Astro): `status: Status`.
- `Monogram` (Astro): `label, family, size`.
- `ReadingModeSwitch` (React, `client:load`): four segmented buttons; sets `document.documentElement.dataset.readingMode` and stores `atlas:reading-mode`. `ThemeToggle` (React, `client:load`): system, light, dark; sets `data-theme` (removes it for system) and stores `atlas:theme`. `Base.astro` contains an inline pre-paint script that applies both from storage (wrapped in try/catch) so there is no flash.
- `Mode` (Astro): `eli5?: boolean; spec?: boolean; practitioner?: boolean; ste?: boolean` → `data-modes` string.
- `FieldTable` (Astro): `fields: {name, type, required, description, specRef?}[]`, `caption`, `specVersion`. Fields are passed inline from the MDX.
- Diagram freshness: `pnpm diagrams:check` (also run by `pnpm check`) regenerates the Mermaid sources in memory and recomputes every render hash without a browser, and fails when a committed `.mmd` or SVG is stale; run `pnpm diagrams` to refresh.
- `MermaidDiagram` (Astro): `id: string` → inlines the theme-neutral `src/generated/diagrams/<id>.svg` once (its theme colors are `--dc-*` variables from `colors.css`); a diagram the renderer kept as two files is inlined twice (`<div class="diagram" data-theme-variant="light|dark">`) and CSS shows one. Caption from DiagramMeta or flow/state title, alt text, source-of-truth link. If the SVG is missing, renders the `.mmd` source in a `<pre>` with a "not rendered" note (never fails the build).
- `FlowPlayer` (React): `flow: Flow`, `sourceIndex`. Controls: play, pause, step back and forward, speed. Shows the actor lanes, the current arrow, the step detail, the payload (format-aware, Shiki not required; a plain `<pre>`), a trust-boundary highlight when `crossesTrustBoundary`, failure branches as a toggle, and a "spec" link from `specRef`. Keyboard: left and right arrows, space. Reduced motion: no animations.
- `StateMachineExplorer` (React): `machine: StateMachine`. Renders states as nodes in a simple layered layout (no dependency; or `@xyflow/react` when it stays under 60 KB gz for this island), click a transition to see trigger, API call and spec reference.
- `Quiz` (React): `questions: QuizItem[]`, stores results in `atlas:quiz:<slug>`. `Flashcards` (React): `cards`, flip, mark known, stores `atlas:cards:<slug>`.
- `NotesPanel` (React): `scope: string` (protocol slug), per-section Markdown notes in `atlas:notes` (one JSON object keyed by `<slug>/<sectionId>`), export and import JSON and Markdown; the global `/notes/` page uses the same store.
- `ProgressRing` (React): sections read over sections total (from `atlas:read:*`).
- `CommandPalette` (React, `client:idle`, mounted in Base): Cmd+K or Ctrl+K, `/` when not in an input; searches `search-index.json` with Fuse.js and Pagefind for full text; shortcuts `g h`, `g c`, `g s`, `j`, `k`, `?` in `lib/shortcuts.ts`.
- `GlossaryTerm`: build-time rehype plugin `lib/glossary/rehype-glossary.ts` wraps the first occurrence per section of each glossary term (or alias) in MDX text nodes with `<button type="button" class="term" data-term="<id>" aria-describedby>`; skips headings, code, links and existing terms. A small vanilla script in Base shows a tooltip with the plain definition and a link to `/glossary/#<id>`.
- `BubbleUniverse` (React, `client:visible`, home only): props `protocols: ProtocolMeta[]`, `relations: Relation[]`, `orbit: OrbitMeta[]`, `personaMap`. D3 force layout with four layout modes (constellation, layers, rails, timeline), hover card, relation edges, orbit toggle, persona filter, keyboard navigation (tab to each bubble, Enter opens). Under 640 px the island is replaced by the card list with a "View universe" button.
- `CompareMatrix`, `PickTwoDiff`, `RadarChart` (React) on `/compare/`; `StackMap`, `ControlsMap` (React with `@xyflow/react`) on `/stack/` and `/controls/`; `Timeline` (React) on `/timeline/`.

## 7. STE files and linter

`ste.mdx` body uses these Astro components (in `components/ste/`), which the linter recognizes by name:
- `<SteDescription>` paragraphs (descriptive rules, 25 words per sentence, 6 sentences per paragraph).
- `<SteProcedure title="Pay for a resource with x402 (agent)">` containing an ordered list; each item is one instruction (20 words, imperative start).
- `<SteCaution>` and `<SteNote>` (safety instructions: signal word, command or condition, risk).
- `<SteTerms>` a definition list of technical nouns and technical verbs.
`scripts/ste/lint-ste.ts` parses the MDX as text, segments by component block, applies the checks in private/ATLAS_PROMPT.md 9.4 with `compromise`, writes `src/generated/ste-report/<slug>.json` `{protocol, sentences, maxProcedureWords, maxDescriptiveWords, flags:[{rule, severity, text, blockType}], passed}` and exits non-zero when any procedural sentence exceeds 20 words or any descriptive sentence exceeds 25. `--protocol <slug>` limits the run. The linter treats code spans, URLs and field names (tokens with dots, underscores, hyphens inside backticks) as single words; the technical-noun allowlist lives in `src/lib/ste/technical-nouns.json`.

## 8. Playgrounds

`src/playgrounds/<slug>/Playground.tsx` default-exports a React component with no required props. Everything runs client-side. Signing uses WebCrypto (Ed25519, ECDSA P-256) or `viem` local accounts with keys generated at mount, on fake chain ids (for example `eip155:31337` or `eip155:424242`) or fixture data. Every playground renders inside `PlaygroundFrame` which shows "Simulation, no real funds", the spec version the simulation follows, and a reset button. Pure logic (encoders, constraint evaluators, signature helpers) lives in `src/playgrounds/<slug>/lib/*.ts` with Vitest tests in `tests/unit/playgrounds/<slug>.test.ts`.

## 9. Scripts

- `scripts/flow-to-mermaid.ts`: for every flow, emit `sequenceDiagram` with `participant` lines (label from actor), `autonumber`, arrows (`->>` for requests, `-->>` for responses: a step is a response when its label starts with a status code, "return", "respond", "200", "402" or `from` was the previous `to`; keep it simple and deterministic), `Note over` for `crossesTrustBoundary`, `alt`/`else` blocks for `failures`. For every state machine, emit `stateDiagram-v2` with `[*] --> initial`, transitions labeled by trigger, terminal states to `[*]`. Output `src/generated/mermaid/<id>.mmd`. Also emit `src/generated/mermaid/index.json` listing ids, kinds and titles. Also generate the accessible description text via `lib/flows/describe.ts` into the index.
- `scripts/render-diagrams.ts`: collects `src/content/diagrams/*.mmd` and `src/generated/mermaid/*.mmd`; starts Playwright Chromium once; loads a local HTML page that imports `node_modules/mermaid/dist/mermaid.esm.min.mjs`; renders each diagram twice with theme variables derived from tokens (light and dark: read the values from `tokens.css` with a small parser, map to Mermaid `themeVariables` such as `primaryColor`, `primaryTextColor`, `lineColor`, `noteBkgColor`, `fontFamily`), each theme in its own pass on a fresh page load so Mermaid's id counters match; `scripts/lib/neutral-svg.ts` folds the two renders into one `src/generated/diagrams/<id>.svg` whose differing colors are `var(--dc-<light>__<dark>)` (in the style block and style attributes directly, through an added style declaration for `fill`/`stroke` attributes), writes the variables for both themes and print to `src/generated/diagrams/colors.css` (imported by `global.css`) and records the pairs in `index.json`; a diagram whose renders differ in structure keeps `<id>.light.svg` and `<id>.dark.svg` with a warning. Uses the same font family names as the site. Fails the script (not the site) on a Mermaid syntax error and prints the diagram id. `--only <id>` for one diagram. Skips unchanged inputs by content hash (`index.json` stores hashes).
- `scripts/check-coverage.ts`: per protocol, applies private/ATLAS_PROMPT.md 14.2 thresholds (sections A to T present in the rendered template, which means: the MDX exists and every sidecar exists; practitioner words >= 2000 counted outside `<Mode>` blocks; ELI5 words 200 to 350 inside `<Mode eli5>`; at least one `<Mode spec>` block with a `FieldTable`; diagrams >= 6 counting mainFlow, stateMachine and `meta.diagrams`; required diagram types covered by DiagramMeta types plus the flow and state; resources >= 12; publications >= 8 with this protocol in `protocols`; personas >= 4; threats >= 8; faq >= 8; open questions >= 6; quiz 10; flashcards 15; glossary terms whose `protocols` include the slug >= 10; timeline events >= 8; every claim in claims.json has sources; every claimId referenced anywhere exists; unverified claims count reported). Reads `coverage-waivers.json`. Prints a table, writes `src/generated/coverage.json`, exits non-zero on unwaived failures. `--protocol <slug>` limits the run.
- `scripts/style/lint-style.ts`: scans `src/content/**` for U+2014 (fail), banned phrases from `scripts/style/banned-phrases.json` (fail, case-insensitive, whole phrase), and practitioner sentences over 35 words in `index.mdx` (warn). Exit non-zero on failures.
- `scripts/verify/validate-content.ts`: parses every content file with the Zod schemas (same as Astro would) and reports the first error per file with path; exits non-zero on any error.
- `scripts/verify/verify-sources.ts`: every claim source id exists in `sources.json`, every source has `accessed`, no orphan sources (warn), no duplicate ids, every `sources` array in every sidecar resolves.
- `scripts/verify/verify-citations.ts`: re-verifies publications through DataCite, Crossref or DOI negotiation; title match (normalized, 85 percent token overlap) and first-author match; polite 300 ms delay; `--offline` skips network and only checks shape.
- `scripts/verify/check-links.ts`: HEAD then GET every URL in sources, resources and publications with 3 retries, 2 concurrent per host, 400 ms spacing; 404 or 410 fail; 403 and 429 from hosts in `scripts/verify/bot-blocking-hosts.json` warn; writes `src/generated/link-report.json`.
- `scripts/verify/merge-research.ts`: merges `research/protocols/*.sources.json`, `research/orbit.*.json`, `research/policy.json`, `research/market.json`, `research/ste.sources.json` into `src/content/sources/sources.json` (de-duplicated by URL, first id wins, later ids recorded as `aliases` in a side map `src/generated/source-aliases.json`), and `research/publications.*.json` into `src/content/publications/publications.json`. Copies `research/protocols/<slug>.claims.json` to `src/content/protocols/<slug>/claims.json`.
- `scripts/data/*`: fetchers write `src/data/snapshots/<source>/<date>.json`; copy the latest to `src/generated/<source>/`. Never throw; log and keep the previous snapshot. `GITHUB_TOKEN` optional (falls back to `gh auth token` when available, then unauthenticated).
- `scripts/build-sw.ts`: after `astro build`, walks `dist/`, writes `dist/sw.js` (precache HTML, CSS, JS, SVG, fonts and the Pagefind runtime up to a size cap, while the Pagefind index chunks and fragments are cached cache-first the first time a search loads them; network-first for HTML with cache fallback; cache-first for hashed assets and those chunks) and `dist/manifest.webmanifest`; Base.astro registers `/sw.js` only in production and links the manifest.
- `scripts/build-search-index.ts`: runs before `astro build` (in `pnpm build`), writes `src/generated/search-index.json` with pages, sections, glossary terms, resources and publications.

## 10. Storage

`src/lib/storage.ts`: `getItem(key)`, `setItem(key, value)`, `removeItem(key)`, `getJSON(key, fallback)`, `setJSON(key, value)`. Every call is wrapped in try/catch with an in-memory `Map` fallback. Keys are prefixed `atlas:`. Nothing ever leaves the browser.

## 11. Accessibility and performance

- WCAG 2.2 AA: visible focus (tokens `--focus`), skip link, landmarks, every island keyboard operable, every diagram with a text alternative, color never the only channel (ring styles, labels, dots with text).
- Home JavaScript under 200 KB gz before the universe hydrates: D3 is imported from submodules (`d3-force`, `d3-scale`, `d3-selection`, `d3-transition`, `d3-zoom`) inside the island only.
- Respect `prefers-reduced-motion` everywhere (tokens set durations to 0).
- `public/_headers`: CSP without `unsafe-eval` (`script-src 'self' 'wasm-unsafe-eval'` for Pagefind; `style-src 'self' 'unsafe-inline'` because Astro scopes styles inline; `img-src 'self' data:`; `connect-src 'self'`), `Referrer-Policy: no-referrer`, `Permissions-Policy` denying camera, microphone, geolocation.

## 12. Writing rules for everything under src/content

See private/ATLAS_PROMPT.md 2.6: no em dashes, no banned phrases, US spelling, sentence case, YYYY-MM-DD, acronyms expanded on first use per page, every number with an "as of" date, every claim cited with `<Cite ids="clm-..." />`.

## 13. Merge pipeline (so eight writers never edit one shared file)

Writers only create files under `src/content/protocols/<slug>/`, `src/content/flows/`, `src/content/states/` and `src/content/diagrams/`. Shared files are assembled by `scripts/merge-content.ts` (run by `pnpm merge`, and first in `pnpm build`), which is idempotent and deterministic:

| Writer output (per protocol) | Merged into | Rule |
|---|---|---|
| `protocols/<slug>/sources.json` (Source[]) | `src/content/sources/sources.json` | union by id; conflicting records for the same id: the sidecar wins and a warning is printed; URLs normalized for duplicate detection; `src/generated/source-aliases.json` records id aliases |
| `protocols/<slug>/compare-cells.json` `{cells: CompareCell[33], radar: [6 axes], controlsCells: ControlCell[14]}` | `src/content/compare.json` (cells, radar) and `src/content/controls-map.json` (cells) | replace the protocol's rows; dimensions and controls lists stay fixed |
