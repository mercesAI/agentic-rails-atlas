## What changed outside the site
- 2026-11-16 to 2026-11-19: mppx went from 0.19.0 to 0.21.1 in five releases, 0.19.1, 0.20.0 and 0.20.1 on 2026-11-16 and 0.21.0 and 0.21.1 on 2026-11-19; 0.21.1 was still the npm latest on 2026-11-21. By their pull request texts, 0.20.0 (PR #1300) and 0.21.0 (PRs #1325, #1326, #1184, #1315 and #1329, with the Zone fixes #1309, #1313 and #1310) fix payment-boundary flaws that have no GHSA or CVE: session retries could bypass stream metering, a failed request could remove a newer request's replay claim so that one payment authorized a second response, a delegated signer could pose as a session's funding payer, clients paid challenges that named a credential header such as X-Payment, and one Zone settlement could pay a challenge twice. Both releases need migration (billable per-item session streams call stream.charge() before any work, and billable SSE proxy sessions need unitType request; proxy replay needs a stable replay.authority or fails at startup), so six releases after 0.14.1 are now breaking. The repository still lists five mppx advisories, the newest of 2026-07-01. README.md is identical from 0.19.0 to 0.21.1, so the code samples stay verbatim under 0.21.1 labels. TIP-1166 voucher support (#1307, merged 2026-11-20) and new core and Tempo-only entrypoints (#1340) are merged but unreleased. The places that named 0.19.0 as of 2026-11-14 (SDK row, compare cells, checklist, persona step, resource note) now name 0.21.1.
- 2026-11-16: mppx 0.19.1 added a provider that checks Personal Agent Protocol 1.0 (Poppy) sessions before any payment challenge (PR #1291, merged 2026-11-14), 0.20.0 an ERC-8004 identity provider (PR #1304) and 0.20.1 an attestation issuer, Tempo ID attestations and x402 sign-in-with-x. With the ERC-8004 provider the agent signs each request with its wallet and sends Agent-Id and Agent-Signature; the server reads getAgentWallet from the Identity Registry, on Tempo mainnet by default, accepts an EOA or ERC-1271 signature for 300 seconds plus 60 seconds of tolerance (single use only with a store), and counts a tempo charge from that wallet as proof, while hash credentials, sessions, Zones and other methods need the request signature. It reads no reputation data. These are SDK features that no MPP draft specifies; mpp.dev's identity page lists neither provider (docs PR #1244 is open), and mppx PR #1332 (opened 2026-11-19, open) would bind ERC-8004 checks to a configured origin. pympp 0.24.0 and the Rust crate mpp 0.21.0 added identity providers of their own the same day.
